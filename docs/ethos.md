# Ethos

Why this exists, in the order the ideas arrived. The spec says what; this says why. No product is
named here on purpose: the ideas are older than any of the machines they were tried on.

## Context is the scarce resource

Every token an agent reads costs money and, when irrelevant, costs quality. Today context is
assembled by code: retrievers, prompt templates, skills files, summarizers, each its own system,
none auditable. Here context is a property of the graph. What a principal can name bounds what it
can read; depth and salience shape the rest; a named serialization caches it and replays it. The
rules that set permissions set context cost. One predicate answers "may you?", "what do you see?"
and "what did that cost?".

## Scope is attention

The same rule that keeps an agent out of what it may not touch keeps its prompt small. A marketing
agent sees the brief and the positioning; the product agent sees the positioning and the plan; the
developer sees the plan and the code. Each pays for exactly its slice, each slice stays small while
the whole keeps growing, and the grant that drew the line is the record of who knew what. So a world
gets cheaper to work in as it gets richer, which is the opposite of a transcript, which gets worse
with every week of history.

## Richness is affordable because the agent does the setup

The systems you lived inside lost to files and pipes because their richness had a price paid in
human attention: name everything, declare types, write presentations, mount namespaces, document
inside the system, keep grants current. People will not do that, so the lazy system won. An agent
will do all of it, cheaply, and the product of the ceremony is exactly what the agent needs to work:
its own context. Setup produces instruction fields, bindings, and memory, which improve the next
resolution, which makes the next task cheaper. The architecture can be as baroque as the work needs,
because upkeep is the agent's job and the knowledge of how to use the system travels with the
objects themselves. The world explains itself. Its first resident sets itself up.

## The world is the harness

There is no agent program outside the world. The loop that interprets, resolves, serializes,
evaluates, and acts is kernel code, one per process-driven principal, with no state outside that
principal's fields. Sessions are streams, tools are actions, subagents are principals, channels are
routes, cron is a trigger, memory is authored fields. Everything a harness did is a named object with
a record. And the world carries the source it runs: its own resident can change it, test it, cut a
release and restart onto it, and the swap waits for a person's own card.

## People, agents, and appliances are one class

A person, a process, and an office appliance share one class, one namespace model, one API; a flag
says what drives each. The product a team builds is itself a principal, so the team is observable:
who touched what, under which grant, from which inputs, at what cost. A pile of files cannot be
observed at any tooling budget. A principal can.

## Naming is the mechanism

Everything has a name. A name resolves for a principal or it does not, and that one predicate carries
access, attention, cost, and audit. Names are location free; location is a property of the object,
held by the adapter that backs it. Move a thing and every reference, memory field, and serialization
that named it still resolves. A reference in text is a real reference: a span, resolved for the
reader, never a string that looks like one.

## The log is the truth

No image holds the system. Every object has a stream; present state is a fold over it; a run is a
value with a name. The single image is what killed the ancestors. Streams federate; images do not.
A world is a value: back it up, export it, fork it, promote the fork, link it to another world, and
the same grammar holds across all of them.

## The listener makes it legible

The agent pays for richness in setup; the person is repaid only if the client renders the record so
that inspection is understanding. The world owns structure. The client owns legibility, and a correct
world that cannot be read has failed the person. Visualization is first-order work, and the client is
a serious piece of software, native and fast, with text quality that respects a reader. The record is
the interface: nothing is hidden in a log file, and nothing needs one.

## An agent has a presentation layer

An agent in a terminal pane, scraping its own output and reporting in walls of text, is not a way for
a program to work with a person. Here an agent presents a view, opens a pane on your screen, hands
you a card that says exactly what will run, cites a path that opens at the line, and leaves a notice
that reaches your phone. The screen is a thing in the world like everything else, so a pane lives on
when the client closes and the same panes open on the next machine. You never have to leave.

## Reviving the ancestors into the future

The evaluating notebook, the inspectable world with actionable references, the system you change
from inside, the shared domain model with provenance, the explicit job, the wired dataflow, the
integrated machine whose operating system was its database, the groupware document with typed fields
and an access list, the expert system that showed its work, the resident agent loop, durable memory.
Each piece was proven once by people with worse tools. Each is native here, without the single image
that killed the vessel it came in. The missing tenant has arrived: a workforce of processes that
needs the same names, the same record, and the same room as the people it works beside.

## How we build it

No special cases for demos. Compose from the fourteen classes or write down why they are not enough.
The log is the only state. One access path. Names from the ontology. A gap between spec and code is a
finding, written down, never a silent divergence. From the first green kernel-zero, the development
agents work as principals inside the world they are building. The world proves itself on its own log,
and the proof is published.
